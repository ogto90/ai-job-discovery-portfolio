# Security policy

This personal project supports the current `main` branch. Older commits and
unreleased branches are not maintained as separate versions.

## Report a vulnerability

Use GitHub's **Report a vulnerability** form on the repository's Security tab
when it is available. It creates a private report for the maintainer. Do not
put a vulnerability, credential, CV, or other personal data in a public issue.

If the form is unavailable, use the maintainer's
[GitHub profile](https://github.com/ogto90) to request a private contact method
without including exploit details. Collaborators on a private copy of this
repository may open an issue visible only to its collaborators.

Include affected code or workflow, a minimal reproduction using synthetic
data, expected and observed behavior, and potential impact. The maintainer
will acknowledge reports as capacity allows, investigate privately, and use a
security advisory for coordinated disclosure when appropriate. Do not test
against another person's data or the maintainer's live services.

The [threat model](docs/security-threat-model.md) records known limitations.
An issue already listed there can still be reported if you have a new exploit,
impact, or practical fix.
